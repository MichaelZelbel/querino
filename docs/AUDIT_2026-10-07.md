# Querino review, 7 October 2026

Bugs, architectural flaws and the engineering system around them, one week after the
2026-09-30 audit. Everything fixed below is on `main`, applied to the production database,
deployed and published. Fourteen migrations (`20261007120000` to `20261007130000`), all 30
edge functions redeployed, and the site published through Lovable.

Five reviewers worked in parallel, each on its own slice: edge functions, the database as it
really is in production, frontend pages and components, the frontend data layer, and the
tooling plus production health. Each traced a suspected bug through the real call path and,
where data allowed, checked its precondition against production read-only. Earlier audits
(2026-08-20, 09-09, 09-23, 09-30) were not re-reported. After the fixes, two more reviewers
read the whole diff only for regressions the fixes had introduced; what they found was fixed
before anything shipped.

## The most serious findings

1. **The Refine button deleted the end of long prompts.** `refine-prompt` cut its input at
   16,000 characters and "Update prompt" saved the model's rewrite of that part as the whole
   prompt. Two live prompts are longer. The 2026-09-30 audit fixed exactly this for the coach
   and translation and missed this function. It now refuses with 413 before any charge.
2. **AI moderation read only the first 4,000 characters.** 27 of the 165 public artifacts
   were longer, so their tails had never been classified, and anyone could publish 4,000
   harmless characters followed by anything. The whole text is now read in overlapping
   12,000-character slices, side by side, and a row says how much was read when an artifact is
   longer than eight slices.
3. **A team invite outlived its maker's right to make it.** A removed or demoted admin could
   keep an admin invite, possibly set to never expire, and come back as admin. The invite now
   needs a maker who is still owner or admin, losing that right deletes the invites, and an
   invite lasts at most 30 days.
4. **Edits by teammates were charged to the author.** A suspended member could publish
   through a teammate's team artifact, and violating text a member wrote got the author the
   strike, the mail and eventually the suspension. The editor now answers for the edit; when
   several people edited the text while a review was pending, nobody is struck automatically.
5. **Admin balance changes were never recorded.** The audit row went to a table the browser
   may not write, so every change went unrecorded and the toast said so. Change and record now
   happen in one database function.
6. **The "similar prompts" index returned a fraction of the matches.** Four `ivfflat` indexes
   with 100 lists on tables of 0 to 218 rows, searched with one probe: 364 related prompts
   returned where an exact search finds 936, and 39 prompts got none. Dropped; an exact scan
   is instant at this size, and the migration says when to add HNSW.
7. **A security test had quietly changed a live setting for a month.** Spec 19 switched the
   prompt metadata model on 2026-09-09 and its restore never landed, so every later run took
   the test's model for the admin's choice. Restored to the admin's model (recorded in the
   spec's own comment of 09-08), and specs 18 to 20 now restore every column and fail loudly
   when the restore does not land.

## Fixes by area

### Database (migrations `20261007120000` to `20261007130000`)

- An artifact's owner can no longer rewrite the text of someone else's suggestion, which then
  showed that person's name on words they never wrote (120000). A suggestion now remembers the
  text it was written against, and the review warns before accepting it undoes later edits.
- `created_at` is the server's on every table whose order a visitor sees, and on invites: an
  author could date a prompt 2999 and pin it to the top of Trending and Newest (120100).
- Invites need a maker who may still invite (120200, above).
- The editor answers for an edit (120300, above).
- Comments are moderated by the database: a suspended account cannot comment, each comment
  gets its own review row (a second comment on the same artifact used to be skipped), and a
  violation replaces the text with a notice instead of deleting the replies with it (120400).
- A seat on a team comes from an accepted invite. An owner or admin could seat any Premium
  user unasked, which also told them who has Premium (120500).
- Indexes on the foreign keys and filters that had none (120700).
- Activity on a team's item reaches the team's feed; comments and suggestions never did
  (120800).
- Counted copies cannot be traced back to the visitor: the "day-salted hash" was salted with
  the public date. The key is now an HMAC under a random daily key no browser role can read,
  an IPv6 visitor counts once per /64, and the client-written `x-forwarded-for` fallback is
  gone. A probe function, created and dropped the same afternoon, showed `cf-connecting-ip` is
  always present and that Cloudflare refuses a request that brings its own (120900).
- Exact similarity search (121000, above).
- A blog post keeps its address when its title changes; the trigger used to move it, and the
  editor's next save moved it back (121100).
- The blog-media bucket takes images up to 10 MB, no SVG (121200).
- Admin balance changes are applied and recorded together (121300, above).
- AI insights are written only by the `ai-insights` function. An owner could post any "AI
  analysis" onto their own public prompt (130000, applied after the new site was live).

### Edge functions

- `refine-prompt` refuses what it cannot see whole (above).
- Moderation reads the whole text, handles comments, strikes the editor, caps its output and
  keeps its tick inside the platform's 150 s limit including the violation mails.
- `mcp-server` edits require the same team membership the website's policies require; a
  member removed from a team could still rewrite its artifacts through an old token, and the
  team's GitHub sync would push the result.
- Every call site has an output budget, used as `max_tokens` unless an admin set one and for
  the credit hold. An answer the provider cut off is settled for what it used and refused, so
  no partial rewrite can be saved over someone's content.
- `ai-insights` reads the item itself, checks the caller may analyse it before charging, and
  saves the row with the service role.
- `notify-admin` no longer logs users' email addresses (the 09-30 commit said it did not).
- `menerio-link-callback` pins the exact callback path, not only the host.
- Timeouts on the outbound calls that had none; reads past 1,000 rows page instead of being
  cut silently (model catalogue, allowance batch, admin presets).
- Translation keeps a prompt kit's `## Prompt:` markers in English.

### Frontend

- Old addresses work for crawlers: a pre-slug UUID or a renamed slug answers 301 on the
  server, a true miss 404, a database error 500. All three used to be a 200 "Not Found" page
  with `noindex`, so Google dropped renamed prompts.
- Detail pages take their row from the route loader and fetch it once (open since 09-23); a
  private row loads once more in the browser with the session, and its tab title is right.
- Prompt lists no longer download every row's embedding: a Discover page of 24 prompts fell
  from about 545 KB to 39 KB, and a large Library from 3.7 MB of internals to the text it
  shows. One list hook now serves all four artifact types, with paging and a stable order, so
  skills, workflows and kits can load past 60 and prompt search is ordered before its cap.
- One Discover search pays for one embedding, not four.
- The prompt-kit editor no longer merges prose after a prompt into that prompt; its toolbar
  offers only what the public kit page can render.
- Importing a standard `SKILL.md` keeps its frontmatter.
- The suggestion review shows a real line diff and warns when the artifact changed since.
- Create Team lands in the new team; pins follow the workspace; credits show the real plan
  base; a failed teams load no longer resets the workspace; coach chats are cleared on sign
  out; cards offer Edit to teammates who may edit; comment replies and edits keep their text
  on failure; a comment with replies is blanked instead of deleting the replies; the one-time
  MCP token cannot be lost to a stray click; plus about twenty smaller fixes in the admin,
  blog, Menerio and settings screens.
- Security headers: `object-src 'none'`, `base-uri 'self'` and a Permissions-Policy. There is
  deliberately no `script-src` yet: TanStack Start's inline hydration scripts would need
  nonces first.

### Tooling

- One lockfile. CI installed from `package-lock.json` while Lovable built from a stale
  `bun.lock`: 28 of 96 direct dependencies differed. `bun.lock` is now the only one and CI
  installs from it frozen. Tiptap 3.31 and prosemirror-view 1.42.6 close two editor
  advisories (paste XSS, attribute injection); nine unused editor extensions are gone.
- The public-pages checks fail when anonymous visitors see nothing, instead of skipping.
- `check-migrations` also catches `ALTER ... DISABLE ROW LEVEL SECURITY`, `ALTER FUNCTION ...
  SECURITY DEFINER`, a view switched to `security_invoker = off`, and quoted bodies.
- ESLint's `any` rule is a warning again (a Lovable commit of 08-24 had dropped that, so
  `npm run lint` failed on a clean tree); CI type-checks the frontend.
- Spec 10 can no longer claim real users' Menerio sync rows; the run lock cannot wait on
  itself; the network-stall retry fits the test timeout.
- New spec 29 runs one rolled-back probe per finding of this review (33 lines).

## What production showed

- Healthy: 0 failed cron runs of 20,368 in seven days, no overlaps, every pg_net response
  200, no stuck queue rows, no open credit reservation, 0 server errors in six days.
- Every migration was rehearsed on production in one transaction ending in a raised error,
  with a probe that acts as each person involved. Run against the old schema (the 20 lines
  that need no new objects), every hole said FAIL and every ordinary flow OK; with the
  migrations, all 33 lines said OK. After applying, the same probe ran against production.

## Deployed

- Database: 14 migrations, recorded in `supabase_migrations.schema_migrations`, the last one
  (`20261007130000`) only after the new site was live; types regenerated.
- Edge functions: all 30, from commit `70fa562`.
- Site: Lovable deployment `16a82819` (commit `4934a6e`). Proven from outside: an old UUID
  address and a renamed slug answer 301 to the current one, a missing prompt answers 404 with
  its message in the HTML, and the new headers are served.
- One live setting restored: the prompt metadata call site's model, which spec 19 had left on
  its override since 2026-09-09.

## Open

- Blog list, category and tag pages render placeholders on the server (there are no posts).
- `markdown-it` (via tiptap-markdown) has a moderate slowdown advisory; no fixed release fits
  the current range.
- From earlier audits: failed MCP sign-ins are not rate limited; the avatars bucket lists file
  names; deleting a team cannot clean its GitHub repository; the sign-up cap can be overshot
  by simultaneous sign-ups (24 of 100 accounts today).
- `/library/$slug/versions` is reachable only by typing it; it now uses the shared restore
  and can be deleted.
