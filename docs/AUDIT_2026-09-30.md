# Querino audit, 30 September 2026

Everything fixed below is on `main`, applied to the production database, deployed and
published. Commits `81a904d` to `38343ab`. Fourteen migrations applied and recorded
(`20260930100000` to `20260930120200`), 19 edge functions redeployed, and Lovable deployment
`7912da49` serving querino.ai. The live security suite passes 187 of 187 on a developer
machine and 176 of 176 in CI (11 skip there by design). `check-public-pages` reads 137 of
137 pages.

Five reviewers worked in parallel, each on its own slice: edge functions, the database,
frontend pages and components, the frontend data layer, and production as it runs. Each
traced a suspected bug through the real call path before calling it one, and fixed it with a
test that fails on the old code. Earlier audits (2026-08-20, 2026-09-09, 2026-09-23) were not
re-reported; their fixes were checked, and one had never taken effect.

## The most serious findings

1. **A 2026-09-09 security fix never took effect.** The stricter rule for saving a team's
   GitHub token was added next to two older rules that only checked the user id, and Postgres
   ORs permissive rules together, so the older ones still let the insert through. Any signed-in
   account could attach a token to any team, and the team's sync would use it whenever the
   owner had none saved. Today the owner of the one affected team has a token saved, so it did
   not happen. Fixed in `20260930100000`, which also drops a departing member's team token.
2. **The AI coach deleted the end of long artifacts.** It sees the first 16,000 characters and,
   in edit mode, returns a "complete" rewrite that the editor saves. 8 of 217 production
   artifacts are longer than that (the longest 69,984 characters). Old code over all 217 rows:
   content lost on 8. New code: lost on 0; a cut artifact is discussed but never rewritten.
   Translation had the same cut and now refuses instead (413, before any charge).
3. **The prompt-kit editor emptied every kit it opened.** It read `title`/`body` where the
   blocks carry `data-title`/`data-body`, and a blank line inside a prompt ended the block.
   Proven on the live site without saving. Production holds no kit yet, so nothing was lost.
4. **Top Rated showed 80 of the 128 public prompts, 48 of them twice.** Most prompts tie at no
   rating, and each page is a separate query, so Postgres ordered the ties differently every
   time. Every paged order now ends in the primary key.
5. **`net._http_response` had grown back to 75 MB, 60% of the database**, about 4 MB a day
   since the one-off truncate of 2026-09-11. pg_net deletes its own rows, so autovacuum never
   runs and the file only grows. Truncated once and vacuumed every hour by cron.
6. **Authors could set their own rating, copy count and search embedding** with a plain REST
   update (Discover sorts by rating). Nobody had: every stored rating matched its reviews.
7. **A suspended account could still publish** through the MCP server or a REST update; the
   check lived only in the website's own call. Now a trigger refuses it on every path.

## Fixes by area

### Database (migrations `20260930100000` to `20260930120200`)

- Team credentials need a seat on that team (100000).
- The moderation stopword list is readable by admins only (100100).
- Ratings, copy counts and embeddings are computed, not written by the browser (100200).
- Background jobs (Menerio sync, embeddings, reviews) no longer move `updated_at`, which fed
  the sitemap's lastmod, "most recent" lists and Menerio's "changed since sync" test; all 171
  synced artifacts looked changed. The embedding lease has its own column (100300).
- Comments and suggestions stay on the artifact and with the author they were written by;
  a review is signed by whoever gives it (100400).
- An author can answer "changes requested": the rule only matched open suggestions, so the
  update touched no row and the page said it had worked (100500).
- An invite names its team and who invited you before you join (100600, open since
  2026-09-23).
- Browser roles lose TRUNCATE, REFERENCES, TRIGGER and MAINTAIN, including for future tables
  (100700, open since 2026-08-20).
- Deleting an artifact deletes its comments, insights, suggestions and collection entries,
  as the delete dialogs already promised (100800).
- Two functions a signed-out visitor never calls are no longer callable by one (100900).
- The pg_net response log is vacuumed hourly; the nightly model sync gets a 30 s timeout
  (110000).
- A suspended account cannot publish by any path (120000).
- A credit reservation settles in the month it was taken in, not the month the call ends in
  (120100, open since 2026-09-23).
- The Prompt Coach's config row is switched back on (120200): during the 2026-09-23 test-suite
  incident the model sync switched it off, the model was restored and the switch was not, so
  admin edits to that row were ignored for a week.
- `scripts/check-migrations.mjs` rule 4: from 2026-09-30 a SECURITY DEFINER function must say
  who may call it. Revoking from PUBLIC alone leaves Supabase's per-role grants in place,
  which is how one such function stayed callable since April.

### Edge functions

- Coach and translation: refuse or discuss content they cannot see whole (above).
- `generate-embedding` reserves credits before it pays, with a provider timeout (open since
  2026-09-23).
- `ai-moderate-content` records each attempt before the paid call, stops after three, and
  times each classification out, so a killed run can no longer re-pay for the same rows
  forever (open since 2026-09-23). The violation email escapes the artifact's title.
- `github-sync` sends all files in one tree request instead of one request per artifact (167
  at once, against GitHub's limit of 100), with hashes computed locally and timeouts. The local
  hash equals the one GitHub recorded for every unchanged artifact.
- `mcp-server` answers 503 instead of 401 when the token lookup itself fails (a database hiccup
  made clients throw away good tokens), and 405 to a client's GET for an event stream it does
  not offer (800 needless 400s a week).
- Every AI call names the credit period it reserved from.

### Frontend

- Pages: dates and counts are printed the same way on the server and in the browser; before,
  React rebuilt 8 of 9 pages for a visitor at UTC+14. querino.ai refuses to be framed
  (`X-Frame-Options`, `frame-ancestors`); the Lovable preview is unaffected.
- Editors: Skill, Workflow and Kit editors no longer say "saved" or "deleted" when the database
  wrote nothing; the blog editor no longer autosaves drafts into a published post; "Save as
  New Version" uses the current version number; publishing again keeps the example output.
- Access: Generate Insights, the comment box and the rating stars appear only for people the
  database will let use them (visitors and team editors were charged for insights they could
  not save). Sign-up checks the same password rules as the server.
- Discover: one toolbar for all four tabs (open since 2026-09-23); search, sort and category
  live in the address, so Back keeps them; error states instead of "none yet". Lists no longer
  download every row's embedding: the skills request fell from 547 KB to 207 KB.
- Download .md then Import lost text on 19 of 217 real rows (multi-line descriptions, `---` in
  a title, bracketed titles); hand-written tags crashed the import. New round trip: 0 lost, and
  old files still read.
- An imported or translated draft survives a reload. The public blog shows an empty page, not
  an error, past its last page. The Library no longer fetches everything visible before the
  user is known. Redirects are checked where they are read and stored.
- Team Settings has the site frame and a way to leave; phones no longer scroll sideways on
  prompt pages and Settings; activity reads as sentences; plus about twenty smaller fixes.

### Tooling

- `tests/web/`: Deno unit tests for the frontend's pure logic (`npm run test:web`, 68 tests).
- CI runs both unit suites; before, it ran neither.
- The live security suite gives every request a deadline and one retry, and says "network
  stall" when that is what happened (this morning's only failure was one). Spec 18 restores
  `enabled` as well as the model. New specs 27 and 28 cover this audit.
- `@radix-ui/react-toast` removed (open since 2026-09-23); lint ceiling lowered to 179.
- Migration history: the 77 files that were applied but recorded under a drifted or missing
  version are now recorded under their own. Every file in `supabase/migrations/` is recorded,
  so a `supabase db push` cannot run an old migration again. One of them would have reopened
  every coach conversation to every signed-in user.

## Open

Decisions that are Michael's (product choices, or changes to people's own data) are listed in
the report he received. The engineering items left open:

- The sign-up cap is enforced in the browser only. Needs an auth hook; a decision first.
- Failed MCP sign-ins are not rate limited. Tokens are long random secrets, so this is cost
  and noise rather than a way in.
- The avatars bucket lets anyone list file names (one file today).
- Search finds whole words only, and a nonsense query still returns "related" prompts; the
  meaning-based search needs a similarity floor.
- Smaller UI items: the AI Insights tab overlaps text on phones; `/reset-password` opened
  directly says the link expired; prompt pages show no date (`published_at` is empty on every
  row); some pages lack a main heading; the profile page ignores the data the server already
  loaded; blog tag and category routes cannot return a real 404 yet.
- Still open from 2026-09-23: detail pages fetch the row again after the server loaded it;
  deleting a team cannot clean its GitHub repository.
- `copies_count` is never incremented anywhere, so every card says "0 copies" and Trending is
  really sorted by rating and date.
