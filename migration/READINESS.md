## 2. Where the earlier risk assessment was wrong

Lovable's assessment of this migration, checked against the repo:

| Their claim | Measured |
|---|---|
| "a large error wave" from strict TypeScript | **39 errors**, fixed in one sitting. Not a wave. |
| `tsconfig` has `noImplicitAny: false` | True, and also `strict: false` and `strictNullChecks: false`. Further from strict than described. |
| browser globals "must be guarded" | 146 occurrences, but only 13 on a server path, and the two most dangerous files already had `typeof window === "undefined"`. |
| "your 34 functions" | 38. |
| Tailwind tokens "ported by hand, a missed token is a silent regression" | Correct, and the largest remaining risk. 76 properties. |
| "the migration lands as a single chat turn and can be reverted from chat history" | True but thin. The tag `pre-tanstack-baseline` is the actual revert path and does not depend on a chat session. |

**My own first number was also wrong**, and worth saying: I reported 36 strict errors.
`tsc --strict` on the command line is overridden by an explicit `"noImplicitAny": false`
in the config file, so that run never had `noImplicitAny` on. The real figure was 39.

## 4. The baseline, and the exact commands to compare against it

Everything lives in `migration/`.

| Artifact | What it is |
|---|---|
| `routes.before.txt` | the 52 pre-migration paths, frozen. The diff target. |
| `routes.txt` / `routes.json` | regenerated by `extract-routes.mjs`; after the migration this is the new tree |
| `baseline-v2/` | **the migration diffs against this.** 106 screenshots taken after the outage fix and after author bylines were restored, so they show the site as it now is |
| `baseline/` | the original 106, taken while the public surface was down. Kept for the record |
| `after-prep/` | the same 106 again; with `baseline` it is the pair that proves the preparation changed nothing |
| `seo-inventory.json` / `.md` | what all 53 routes put in `<head>`, read from the running app |
| `ssr-scan.json` | all 146 browser-global occurrences, classified by when they run |
| `baseline-checks.md` | build, tsc, lint and test output before anything changed |
| `URGENT-public-pages-are-404.md` | the outage |
| `routing-auth-contract.md` | ten behaviours no screenshot covers |
| `visual-regression-checklist.md` | the five v4 mechanics most likely to drop a token |
| `migration-risks.md` | what was deliberately not fixed |

After the migration, run these four:

```bash
# 1. routes: regenerate the tree from the new router and diff against the frozen copy.
#    Expect no output. routes.before.txt is the pre-migration list, kept on purpose.
node migration/extract-routes.mjs && diff migration/routes.before.txt migration/routes.txt

# 2. pixels: re-photograph and compare. Expect 3 or fewer, and only the noisy three.
npm run build
SHOT_DIR=after-migration npx playwright test --config=playwright.baseline.config.ts screenshots
node migration/compare-shots.mjs baseline-v2 after-migration

# 3. head: re-capture and diff. Expect nothing missing.
npx playwright test --config=playwright.baseline.config.ts seo-inventory
git diff migration/seo-inventory.json

# 4. auth: walk migration/routing-auth-contract.md by hand. Nothing automates this.
```

Then delete `src/pages/TokenGallery.tsx`, its route in `src/App.tsx`, and the
`/__tokens` entry in `build-screenshot-urls.mjs`.

**The noise floor is 3 of 106.** Two runs of identical code differ in
`admin@desktop`, `collections_id_edit@mobile` and `root@desktop`, because those pages
render live data. Baseline against after-prep differs in exactly one file,
`root@desktop`, one of those three. The preparation is under the noise.

`baseline-v2` against `baseline` differs in 12 files, and all twelve are pages the
outage had emptied: `root`, `discover`, `admin` and the three detail routes, each in
both viewports. The other 94 are byte-identical, which is a second and independent way
of saying the preparation moved nothing.

`baseline-v2` was then re-taken once more, after author bylines were restored to
logged-out visitors. The same 12 files moved again, each by a few kilobytes, which is
the avatar and the name. The same 94 stayed byte-identical through both database
changes.

## 7. The prompt for whoever runs the migration

> Migrate this Vite + React 18 SPA to TanStack Start with Tailwind v4 and strict
> TypeScript. Strict is already on and the codebase is at zero errors; keep it there.
>
> Hard constraints:
>
> - **Every URL path stays character-identical.** The list is
>   `migration/routes.before.txt`, 52 paths. Dump the new route tree the same way and diff it. `/__tokens` is
>   scaffolding and should be deleted, not migrated.
> - **Auth behaviour stays identical**, and it is not what you would guess: there are no
>   route guards, every guarded page renders sign-in *in place at its own URL*. Do not
>   convert those into redirects. All ten behaviours are in
>   `migration/routing-auth-contract.md`.
> - **Do not touch** `supabase/functions/**`, `supabase/migrations/**`, the database
>   schema, the MCP server, or the Cloudflare worker.
> - **Port all 76 design tokens, do not re-derive them.** They are HSL triples consumed
>   as `hsl(var(--token))`, and custom CSS uses `hsl(var(--token) / 0.08)`. Turning them
>   into complete colours in `@theme` breaks every slash-opacity use silently. The five
>   mechanics to get right are in `migration/visual-regression-checklist.md`.
> - **Move page metadata into route metadata** using `migration/seo-inventory.md`. This
>   is the reason for the migration: today `SEOHead` writes the head from a `useEffect`
>   and renders `null`.
> - **Mount the Tiptap editor client-only.** It initialises against the DOM.
>
> When you are done, say which of the four checks in `migration/READINESS.md` §4 you ran
> and what they returned.
